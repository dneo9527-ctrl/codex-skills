# 活跃任务中的圆桌会议

只在本聊天已有有效圆桌设置，或用户明确要求本次圆桌时使用。日常 `assist` 模式仍请一个合适提供方有界协助。此流程组织当前活跃 Codex 的工作，不建立常驻调度器，不保证闲置聊天自动开始。

## 身份、计划与参与方

先从已核实的部署读取本聊天的 `roundtable`、`roundtable_plan` 和 canonical 总控/提供方策略。精确 `CODEX_THREAD_ID`、`mode=roundtable`、有效主持、`rounds=2` 与计划均须匹配；新独立会议要求服务声明 `roundtable_meetings`。不能用损坏或缺失元数据猜成开启，也不为读取计划启动 Ag 服务；自动启动仍服从原独立偏好。

计划中的参与方只是许可范围。逐一核实当前项目的实际网页会话或 Agy 固定绑定，确认权限、模型、草稿及已有生成状态。没有项目 URL、浏览器工具不可用、登录或额度受阻时如实记录不可用，不改投任意网站、不读凭据、不自动登录/换号。普通开启多个提供方不授权群发；本次明确圆桌只发送与议题有关、各有分工的有限请求。

开始一次会议时保存主题与稳定 `source_id`，沿用服务器返回的 `meeting_id`、冻结主持、参与方和工作会话。创建会议本身不调用模型。恢复时用检查点中的确切会议 ID 查询；不要按最新记录、标题或 cwd 找一场会议接管。创建/记录返回不明时用原标识核对，不新建一场或换来源标识重试。

```bash
python3 /confirmed/console/bridge.py --meeting-create /absolute/meeting-create.json
python3 /confirmed/console/bridge.py --meeting-view MEETING_ID
```

创建文件：`{codex_thread_id, source_id, topic, branch?}`。`branch` 只使用已确认的工作会话；新会议不另建官方 CLI 对话。调用前后保存实际回执，不能把计划当作已发送。

## 提案与互评

第一轮先记录 Codex 实际提案，再分别交给已确认且获准的助手做独立提案。每位参与者最多一次提案、一次互评；选定的外部主持可额外有一次最终总结。讨论请求仅包含必要的议题、真实发言和当前约束，不把整段项目历史反复传给各方。引用其他人的意见时注明已收到、缺席或仍在等待，不能补写缺失发言。

所有参与方（包括 Codex）的首轮槽位得到真实终态后，才进入第二轮互评。互评针对实际提案中的风险、分歧或补充；Codex 也记录自己的实际判断。没有回复的提供方不能被写成“同意”或“无异议”。缺席不自动增加参与方或追加无限轮次。

Agy 用既有 dispatcher 关联会议阶段，沿用官方会话和窗口模型；不要另跑独立 CLI，也不要为展示 Muse 先制造一条 Agy 成功记录：

```bash
python3 /confirmed/console/bridge.py --meeting MEETING_ID --meeting-stage proposal \
  --task-file /absolute/agy-proposal.txt --out /absolute/run-01 --no-wait
```

互评/选定主持总结使用 `review` / `summary`。原生 Agy 状态和正文从关联的真实任务派生；不要用外部事件伪造 Agy 完成。排队耗时和模型执行耗时分开观察，不抢占其他窗口任务，也不因等待而擅改保存的模型或账号。

Muse/Claude 等网页贡献通过会议事件独立记录，**无需等待 Agy 返回**。事件文件包含 `meeting_id, codex_thread_id, source_id, provider, stage, status`，并按实际事件提供 `text, source_url, detail`：

```bash
python3 /confirmed/console/bridge.py --meeting-event /absolute/observed-event.json
```

在网页最终发送前再次核实权限、会话 URL 和实时输入。先记录 `sending` 意图，再执行一次发送；观察到新请求进入原会话后记 `waiting`。点击回执不明时保持待核对，检查原会话，**不换来源标识补发**。已发送任务仍在生成时不能覆盖输入；用户草稿始终保留。

只有实际看到完整、非空的最终回复，才记 `completed`、原文与提供方的具体 HTTPS 会话 URL。Codex 本地贡献使用空来源 URL；网页 URL 不带认证、查询参数或片段。每个事件用不同且稳定的来源标识；同一事件重读复用原标识。该标识用于幂等记录，不是发送许可，也不是模型完成证明。阶段内通常是 `pending → sending → waiting → completed`；已经观察到真实回复可以直接完成，仍须来源核验。终态不可改写；重新读取同一事件复用相同来源标识和相同内容。

尚未尝试、因权限、工具或登录受阻的槽位记 `unavailable` 和简短原因；它仅适用于 `pending`。确认真实任务失败才记 `failed`；确认撤回才记 `cancelled`。已发任务超时且结果不明时保持待核对，不能凭等待时间把它当成未执行并重跑。通过部署支持的查询核实原任务；需取消时只操作已授权且身份明确的任务。外部事件不能取消已关联的 Agy 进程。

## 主持总结、失败与恢复

所有提案与互评槽位（包括 Codex）都到终态后，选定主持依据真实回复归纳方案、分歧、代价和未完成项。主持为 Codex 时记录自己的总结；主持为外部助手时必须取得该助手的真实总结，不能让 Codex 文本冒用它的身份。

主持不可用时保留主持偏好和失败原因；将其总结槽位标为 `unavailable` 并写明原因，或按实际情况记失败/取消。Codex 可以在本聊天作明确标为 Codex 的情况说明，不伪造外部主持总结、不静默换主持。只有必要阶段都真实完成才报告会议完成；缺席、失败、取消或空回复意味着部分完成/未完成。会议状态 `active` / `completed` / `partial` 以及槽位的完成或取消状态，均不能替代对真实来源的核验。

有界等待的检查点要保存精确 meeting/turn ID、网页项目 URL、发送是否确认、已经收到的文本路径及下一步。恢复先查这些原记录；`sending` / `waiting` 不是可安全重发状态。不得自动重试外部发送、扩大权限或以定时唤醒继续开会。已结束的槽位不改写正文；确需重开时先确认新的用户授权和新的会议范围。

最终核对面板中的身份、提案/互评/主持标签、来源链接、真实内容、失败状态与原会话/模型偏好；采纳意见仍由 Codex 独立验证。描述当前回合实际完成的协作，不把 Skill 可用或设置开启说成后台全自动会议已经验收。
